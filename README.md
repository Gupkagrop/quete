# Куэте (Quete)

Экзаменационный веб-проект интерактивной онлайн-викторины с элементами психологической игры, механиками блефа и интеграцией больших языковых моделей (LLM). Визуальный стиль интерфейса вдохновлен ретро-эстетикой 8-битных аркадных автоматов.

Основная цель игры — не просто продемонстрировать эрудицию, отвечая на сложные вопросы, но и запутать оппонентов, придумывая собственные правдоподобные, но ложные варианты ответов (фейки).

---

## Архитектура игрового процесса

Игровой цикл мультиплеера рассчитан на группу от 2 до 8 участников и включает в себя 3 раунда по 3 вопроса в каждом (всего 9 вопросов за игровую сессию).

### Игровой цикл вопроса:
1. Выбор темы. Один из игроков случайным образом назначается ответственным за выбор темы раунда.
2. Генерация вопроса. Интегрированная нейросеть Groq Cloud API генерирует уникальный вопрос по выбранной теме, правильный ответ, а также набор эталонных фейков. Если API недоступно, система автоматически переключается на локальную базу данных (офлайн-режим).
3. Ввод ложных ответов. Игроки за ограниченное время придумывают свой вариант правдоподобной лжи. Если игрок не успевает, система автоматически берет случайный фейк, сгенерированный ИИ.
4. Голосование. На экране выводится перемешанный список ответов: 1 правильный, фейки игроков и ИИ-варианты. Голосовать за собственный вариант запрещено.
5. Расчет очков. Система вычисляет результаты, раскрывает авторство фейков и начисляет баллы.
6. Переход к следующему шагу. Через 10 секунд ожидания лобби переключается на следующий вопрос.
7. Финал игры. По окончании 3 раундов формируется пьедестал почета с итоговой статистикой участников.

### Начисление очков:
* Выбор верного ответа: 10 очков, помноженные на номер текущего раунда (множители x1, x2, x3).
* Успешный блеф (когда другой игрок выбрал ваш фейк): 5 очков за каждый голос, помноженные на множитель раунда.

## Игровые режимы

В проекте реализовано два режима игры:

1. **Мультиплеер (Соревнование):**
   * Требуется от 2 до 8 игроков.
   * Полная запись статистики ответов и побед в профили пользователей базы данных.
   * Синхронизация через веб-сокеты в реальном времени.
   * Доступен игровой текстовый чат для общения участников.

2. **Соло-режим (Одиночный):**
   * Изолированная игровая сессия для одного человека.
   * Состоит из 1 раунда (3 вопроса).
   * Игрок соревнуется с фейками, сгенерированными искусственным интеллектом.
   * Результаты одиночной игры не учитываются в общей статистике профиля и глобальном рейтинге.

## Технологический стек

* **Серверная часть:** PHP 8.1+, архитектура без использования тяжелых сторонних фреймворков для максимального быстродействия.
* **База данных:** MySQL (СУБД взаимодействует через PDO, с подготовленными выражениями и транзакциями).
* **Интеграция с ИИ:** Groq API (модель llama-4-scout-17b-16e-instruct) для потоковой генерации уникального контента.
* **Сетевое взаимодействие:** Ratchet WebSockets (PHP-библиотека для асинхронной работы с сокетами). Для стабильности реализован автоматический резервный полинг через AJAX на случай обрыва WebSocket-соединения.
* **Клиентская часть:** Чистый JavaScript (Vanilla JS), HTML5, кастомный CSS3 без CSS-фреймворков.

## Безопасность и архитектурные особенности

1. **Билетная авторизация WebSockets:**
   Для защиты WebSocket-канала от несанкционированных подключений используется авторизация по одноразовым билетам. При загрузке игровой страницы сервер генерирует временный токен в БД, который клиент передает при рукопожатии сокетов. Сразу после проверки токен аннулируется.

2. **Защита от CSRF-атак:**
   Все действия, изменяющие состояние системы (авторизация, создание комнат, отправка ответов, выход из лобби), защищены уникальными токенами сессий. Токены валидируются с помощью криптографически безопасной функции `hash_equals()`.

3. **Фильтрация ввода и защита от XSS:**
   * Введенные пользователями фейки, сообщения в чате и темы комнат принудительно очищаются на сервере функцией `strip_tags()`.
   * На стороне клиента вывод сообщений чата экранируется с помощью безопасной подстановки текстового содержимого.
   * Имена пользователей при регистрации фильтруются по белому списку символов.

4. **Юридическое соответствие стандартам РФ:**
   * Полное информирование пользователей об использовании файлов cookie.
   * Реализован механизм безвозвратного удаления аккаунта со всеми статистическими записями.
   * Маркировка контента согласно ФЗ-436 (категория 18+).

5. **Кастомная обработка ошибок (403, 404, 500):**
   Для минимизации прерывания игрового опыта кастомные страницы ошибок оформлены в общем пиксельном дизайне проекта и позволяют пользователю вернуться на главную страницу в один клик.

## Развертывание проекта локально

Для запуска проекта на локальной машине необходимы:
* Веб-сервер (Apache/Nginx) с интерпретатором PHP версии 8.1 или выше.
* Менеджер зависимостей Composer.
* Система управления базами данных MySQL.

### Инструкция по установке:

1. Создайте копию настроек окружения из шаблона:
   ```bash
   cp .env.example .env
   ```
   В созданном файле `.env` укажите параметры доступа к локальной базе данных MySQL и ваш ключ API Groq.

2. Установите необходимые PHP-пакеты через Composer:
   ```bash
   composer install
   ```

3. Импортируйте базу данных:
   * Создайте в MySQL пустую базу данных с именем `quete_db`.
   * Импортируйте структуру таблиц из файла `database.sql`:
     ```bash
     mysql -u root -p quete_db < database.sql
     ```

4. Запустите сервер веб-сокетов:
   Откройте терминал в корневой папке проекта и запустите демон сокетов:
   ```bash
   php websocket/server.php
   ```

5. Запустите локальный веб-сервер (например, встроенный в PHP или с помощью OpenServer) и откройте проект в браузере.
