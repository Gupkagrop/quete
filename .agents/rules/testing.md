# Testing Rules

> [!NOTE]
> Правила тестирования бэкенда и клиентского приложения Quete.

## 1. Бэкенд-тестирование (Pytest)
- **Фреймворк:** `pytest` с плагинами `pytest-asyncio`, `httpx` (AsyncClient для эндпоинтов FastAPI).
- **Слой базы данных:** Тестирование с изоляцией транзакций (откат после каждого теста) или временной тестовой БД PostgreSQL / SQLite в памяти для быстрых unit-тестов.
- **Интеграция с ИИ:** Все вызовы к Gemini API в автоматических тестах должны быть замоканы (`mock`), чтобы исключить затраты токенов, задержки сети и недетерминированность.
- **Проверка:** Команда `pytest` должна выполняться со 100% прохождением тестов перед сдачей задач.

## 2. Клиентское тестирование (Flutter)
- **Unit & Widget Tests:** Покрытие бизнес-логики и ключевых компонентов через `flutter test`.
- **WebSocket моки:** Тестирование реакции интерфейса на входящие события реального времени с использованием моковых сокет-каналов.
- **Анализ кода:** Команда `flutter analyze` не должна выдавать ошибок или предупреждений.
