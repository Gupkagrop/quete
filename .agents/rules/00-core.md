# Core Engineering Rules

> [!IMPORTANT]
> Базовые правила и стандарты разработки проекта Quete, обязательные для всех агентов.

## 1. Архитектурные принципы и структура кода
- **Плоская архитектура (Flat Architecture):** Всегда используйте ранние возвраты (`early return`). Максимальная глубина вложенности блоков — не более 3 уровней.
- **Компактные функции:** Длина функций не должна превышать 30-40 строк. Сложная логика декомпозируется на небольшие вспомогательные функции с единственной ответственностью.
- **Строгая типизация (Strict Typing):** Запрещено использование неявных типов или `Any`. Все сигнатуры функций, аргументы и возвращаемые значения обязаны иметь явные аннотации типов.
- **Отсутствие заглушек (Zero Placeholders):** Запрещены комментарии `// TODO`, `pass` в качестве постоянной логики, временные моки в рабочих ветках. Код должен быть полностью рабочим и готовым к эксплуатации.

## 2. Языковые стандарты
- **Идентификаторы в коде:** Все имена переменных, функций, классов, модулей, таблиц и файлов пишутся исключительно на английском языке в соответствии с общепринятыми конвенциями (snake_case для Python, camelCase/PascalCase для Flutter).
- **Комментарии и документация:** Все docstring, комментарии к коду и архитектурные заметки пишутся строго на русском языке.

## 3. Управление секретами и окружением
- Запрещено хардкодить токены, пароли, ключи API (включая Gemini API Key) и секреты в исходном коде.
- Все конфигурационные параметры считываются через переменные окружения (`.env`) с валидацией через `pydantic-settings` на бэкенде.
