# Security Rules

> [!IMPORTANT]
> Правила информационной безопасности проекта Quete.

## 1. Аутентификация и авторизация (Self-hosted JWT)
- **Токены:** Использование пар токенов Access Token (короткоживущий, 15-30 минут) и Refresh Token (хранится безопасно, ротация при обновлении).
- **Хеширование паролей:** Использование стойких алгоритмов хеширования (`bcrypt` или `argon2`). Открытые пароли никогда не сохраняются и не логируются.
- **WebSocket безопасность:** Защита подключения одноразовым тикетом (`ticket`) или передачей JWT в момент хендшейка. Соединения без валидной авторизации немедленно закрываются сервером.

## 2. Защита данных и API
- **Валидация входных данных:** Все входящие запросы и сообщения сокетов валидируются через схемы Pydantic / DTO.
- **Очистка пользовательского контента:** Имена лобби, кастомные темы и введенные игроками фейковые ответы очищаются от HTML/JS инъекций (XSS).
- **Rate Limiting:** Ограничение частоты запросов к эндпоинтам авторизации и генерации контента через ИИ для предотвращения DoS и перерасхода квот Gemini API.
- **CORS:** Строгая настройка разрешенных источников для Web-клиента в production-окружении.
