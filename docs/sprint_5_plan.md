# Спринт 5: Игровой цикл — «Вопрос и Таймеры» (День 29–35)

## Goal Description
Цель пятого спринта — реализовать надёжный переход из лобби в активную игру, запустить серверную State Machine раундов на базе временных меток в Redis (без блокирующих и уязвимых `asyncio.sleep`), обеспечить широковещательную рассылку вопроса раунда через Redis Pub/Sub и синхронизированный обратный отсчёт таймеров на всех клиентах.

---

## 1. Архитектурные решения

### 1.1 Серверная State Machine (Game Engine) и отказоустойчивые таймеры
- Игра состоит из 5 раундов со следующими фазами:
  1. `QUESTION_READING` (20 сек) — чтение вопроса.
  2. `BLUFF_SUBMISSION` (45 сек, Спринт 6) — ввод лжи.
  3. `VOTING` (30 сек, Спринт 8) — выбор ответа.
  4. `ROUND_RESULTS` (15 сек, Спринт 8) — показ очков.
- **Отказоустойчивость таймеров:**
  - Использование `asyncio.sleep` для глобального таймера запрещено (при перезагрузке воркера игра зависнет).
  - Фаза фиксируется в Redis и БД с точной меткой дедлайна: `phase_ends_at`.
  - Переход фаз контролируется планировщиком `GameEngine`, который проверяет актуальное состояние в Redis.
- **Безопасность данных:**
  - Правильный ответ (`correct_answer`) хранится строго на сервере в БД и Redis.
  - Клиентам рассылается **исключительно** текст вопроса (`question.text`).

### 1.2 Синхронизация таймера и рассылка через Redis Pub/Sub
- При смене фазы сервер публикует событие в канал `room:{code}:channel`:
  ```json
  {
    "type": "phase_started",
    "payload": {
      "phase": "QUESTION_READING",
      "round_number": 1,
      "ends_at": "2026-10-01T12:00:20Z",
      "duration_seconds": 20,
      "question": {
        "text": "Текст вопроса..."
      }
    }
  }
  ```
- Клиенты рассчитывают остаток времени относительно серверной метки `ends_at`, компенсируя сетевые задержки.

## 2. Предлагаемые изменения по файлам

### Backend (`backend/`)
- `app/models/game.py`: SQLModel сущности `GameSession` и `Round`.
- `app/services/game_engine.py`: ядро State Machine раундов с фиксацией дедлайнов в Redis и надежным переходом фаз.
- WebSocket обработка команды `start_game` (инициируется хостом).

### Client (`client/`)
- `state/game_provider.dart`: Riverpod провайдер, отслеживающий `GamePhase`, номер раунда и дедлайн `ends_at`.
- `ui/screens/game/question_screen.dart`: экран чтения вопроса (плашка «РАУНД 1 ИЗ 5», 8-bit карточка с вопросом).
- `ui/widgets/pixel_timer.dart`: процедурный 8-bit таймер с изменением цвета (зелёный $\rightarrow$ жёлтый $\rightarrow$ мигающий красный при $<5$ сек).

## 3. План верификации
- **Pytest:** проверка переходов State Machine, устойчивость при проверке `ends_at`, проверка строгого отсутствия `correct_answer` в WebSocket-рассылке клиентам.
- **Flutter test:** виджет-тест экрана вопроса и тиканья `PixelTimer`.
