# Спринт 5: Игровой цикл — «Вопрос и Таймеры» (День 29–35)

## Goal Description
Цель пятого спринта — реализовать переход из лобби в активную игру, запустить серверную State Machine раундов, широковещательную рассылку вопроса раунда и синхронизированный обратный отсчёт таймеров между сервером и всеми подключенными клиентами.

---

## 1. Архитектурные решения

### 1.1 Серверная State Machine (Game Engine)
- Игра состоит из фиксированного количества раундов (по умолчанию 5).
- Фазы раунда:
  1. `QUESTION_READING` (20 сек) — чтение вопроса.
  2. `BLUFF_SUBMISSION` (45 сек, Спринт 6) — ввод лжи.
  3. `VOTING` (30 сек, Спринт 8) — выбор ответа.
  4. `ROUND_RESULTS` (15 сек, Спринт 8) — показ очков.
- **Безопасность:** правильный ответ на этапе `QUESTION_READING` хранится строго в памяти сервера и в БД; на клиенты рассылается **только** текст вопроса (`question_text`).

### 1.2 Синхронизация таймера
- Сервер рассылает точную временную метку окончания фазы: `{"phase": "QUESTION_READING", "ends_at": "<iso_timestamp>", "duration_seconds": 20}`.
- Клиенты рассчитывают оставшееся время локально относительно серверного `ends_at`, что исключает рассинхронизацию из-за сетевых задержек.

---

## 2. Предлагаемые изменения по файлам

### Backend (`backend/`)
- `app/models/game.py`: SQLModel сущности `GameSession` и `Round`.
- `app/services/game_engine.py`: логика переходов State Machine, запуск `asyncio.sleep` таймеров и broadcast-рассылка смены фаз.
- WebSocket обработчик события `start_game` (инициируется хостом).

### Client (`client/`)
- `state/game_provider.dart`: Riverpod StateNotifier, отслеживающий `GamePhase`, текущий раунд и таймер.
- `ui/screens/game/question_screen.dart`: экран чтения вопроса (плашка «РАУНД 1 ИЗ 5», карточка с вопросом).
- `ui/widgets/pixel_timer.dart`: процедурный 8-bit таймер с изменением цвета (зелёный $\rightarrow$ жёлтый $\rightarrow$ мигающий красный при $<5$ сек).
