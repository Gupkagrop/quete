# Спринт 8: Турнирный финал — «Матч и Таблица лидеров» (День 50–56)

## Goal Description
Цель восьмого спринта — объединить раунды в полноценный турнирный матч из 5 раундов с накоплением очков в `session_players`, реализовать переход игры в финальное состояние `GAME_FINISHED`, защиту от повторного голосования на уровне БД, итоговый экран результатов с ретро-пьедесталом почета и обработку события реванша (`rematch`).

---

## 1. Архитектурные решения

### 1.1 Жизненный цикл полного матча (5 раундов)
- Игра состоит из 5 последовательных раундов.
- По окончании фазы `ROUND_RESULTS` раундов 1–4 `GameEngine` автоматически инициализирует следующий раунд:
  - Инкремент `current_round_index`.
  - Загрузка следующего вопроса из пула сессии.
  - Переход в фазу `QUESTION_READING`.
- По завершении 5-го раунда сессия переходит в статус `finished`, а клиентам рассылается событие `game_finished`.

### 1.2 Ограничение на один голос (Защита от накрутки)
- В таблице `votes` действует ограничение **`UNIQUE(round_id, voter_id)`**.
- Игрок имеет право отдать ровно один голос в текущем раунде через WS-событие `submit_vote: {"option_id": "..."}`. Повторные попытки голосования отклоняются с кодом ошибки `ALREADY_VOTED`.

### 1.3 Финальная таблица лидеров и логика реванша
- Итоговые очки считываются напрямую из таблицы `session_players` с сортировкой по `score DESC`.
- Сервер рассылает событие `game_finished` с данными для топ-3 пьедестала:
  ```json
  {
    "type": "game_finished",
    "payload": {
      "session_id": "<uuid>",
      "podium": [
        {"place": 1, "player_id": "...", "nickname": "Champion", "score": 4500},
        {"place": 2, "player_id": "...", "nickname": "RunnerUp", "score": 3000},
        {"place": 3, "player_id": "...", "nickname": "ThirdPlace", "score": 2500}
      ]
    }
  }
  ```
- Хост может отправить событие `rematch: {}`: сервер создаёт новую игровую сессию с теми же участниками `session_players` (сбросив `score = 0`) и начинает матч заново.

## 2. Предлагаемые изменения по файлам

### Backend (`backend/`)
- Добавление `UNIQUE(round_id, voter_id)` в миграцию таблицы `votes`.
- Расширение `GameEngine`: логика цикла из 5 раундов и переход в `GAME_FINISHED`.
- Обработчик клиентского WS-события `rematch`.
- Формирование итогового рейтинга из `session_players`.

### Client (`client/`)
- `ui/screens/game/leaderboard_screen.dart`: экран финального пьедестала почета (1, 2, 3 места) с ретро-кубком и итоговой таблицей всех игроков.
- Кнопки «РЕВАНШ» (отправляет WS-событие `rematch`, доступна хосту) и «ГЛАВНОЕ МЕНЮ».
- Маршрутизация: экран результатов `/result/:code` в `go_router`.
