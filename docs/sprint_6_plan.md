# Спринт 6: Интеллектуальный геймплей — «ИИ-вопросы и Нечеткая валидация» (День 36–42)

## Goal Description
Цель шестого спринта — подключить динамическую генерацию вопросов ИИ (Gemini 1.5 Flash) к активным матчам, внедрить интеллектуальную защиту от раскрытия истины через Fuzzy Matching (нечеткое сравнение с правильным ответом) и реализовать безопасный атомарный досрочный переход фазы блефа при готовности всех участников.

---

## 1. Архитектурные решения

### 1.1 Интеграция вопросов ИИ в игровые сессии
- При старте сессии хост отправляет WS-событие `select_topic: {"topic": "..."}`.
- Вопросы загружаются из кэша или генерируются Gemini. Текст вопроса и 7 резервных фейков (`decoy_fallbacks`) связываются с записью раунда `Round.question_id`.

### 1.2 Нечеткая валидация блефа (Fuzzy Matching)
- **Алгоритм проверки (библиотека `rapidfuzz`):**
  - Нормализация: приведение к нижнему регистру, удаление знаков препинания, артиклей и лишних пробелов.
  - Расчет коэффициента сходства (Token Sort Ratio / Levenshtein Distance).
  - Если схожесть с истиной $\ge 80\%$, ввод отклоняется с кодовой ошибкой `BLUFF_MATCHES_TRUTH`: «Вы указали правильный ответ (или слишком близко к нему)! Придумайте правдоподобную ложь».

### 1.3 Безопасный досрочный переход без Race Conditions
- Событие `player_submitted` рассылает **только `player_id`**, исключая утечку текста блефа.
- Счетчик сданных ответов отслеживается через атомарный инкремент в Redis: `INCR room:{code}:round:{round_id}:submitted`.
- **Защита от сбоя при кратковременном дисконнекте:**
  - Счетчик сабмитов сверяется строго с **зафиксированным количеством участников сессии из таблицы `session_players`**, а не с динамическим списком онлайн-сокетов.
  - Если игрок кратковременно потерял связь, фаза не схлопнется досрочно до истечения полного таймера (45 сек) или до момента, пока он не переподключится и не сдаст ответ.

## 2. Предлагаемые изменения по файлам

### Backend (`backend/`)
- Добавить `rapidfuzz>=3.9.0` в `pyproject.toml`.
- `app/services/bluff_validator.py`: реализация алгоритма нечеткого сравнения (Fuzzy Matching >80%).
- Интеграция `GeminiQuestionService` в пайплайн создания раундов `GameEngine`.
- Атомарная обработка WS-события `submit_bluff` с рассылкой `player_submitted` и проверкой по `session_players`.

### Client (`client/`)
- Обновление `BluffInputView`: вывод ошибки `BLUFF_MATCHES_TRUTH` с ретро-подсветкой.
- `ui/screens/game/widgets/waiting_players_list.dart`: динамический список игроков с галочками готовности.

## 3. План верификации
- **Pytest:** юнит-тесты на Fuzzy Matching (опечатки, артикли, разный регистр), проверка интеграции вопросов Gemini в раунды, проверка сокрытия ответов в WS-рассылке, тест досрочного перехода со сверкой по `session_players`.
- **Flutter test:** виджет-тест отображения ошибки совпадения с истиной и списка готовых игроков.
