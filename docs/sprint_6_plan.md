# Спринт 6: Игровой цикл — «Блеф» (День 36–42)

## Goal Description
Цель шестого спринта — реализовать механику блефа: ввод игроками собственных ложных ответов, строгую серверную валидацию с нечетким поиском (Fuzzy Matching) для защиты от совпадения с истиной, защиту от перехвата ответов до голосования и атомарный досрочный переход при готовности всех участников.

---

## 1. Архитектурные решения

### 1.1 Валидация блефа и нечеткое сравнение (Fuzzy Matching)
- Длина ответа: от 1 до 80 символов.
- **Интеллектуальная защита от раскрытия истины (Fuzzy Matching):**
  - Прямое сравнение строк уязвимо перед опечатками («Aple») и артиклями («An apple»).
  - Сервер выполняет нормализацию (удаление знаков препинания, артиклей, приведение к нижнему регистру) и рассчитывает расстояние Левенштейна / коэффициент сходства.
  - Если схожесть с `correct_answer` превышает **80%**, сервер возвращает ошибку `BLUFF_MATCHES_TRUTH`: «Вы указали правильный ответ (или слишком близко к нему)! Придумайте правдоподобную ложь».
  - Игрок обязан ввести другой вариант до истечения таймера.

### 1.2 Защита от подглядывания (Анти-чит) и атомарный счетчик
- **Защита от читерства:** при успешном приёме ответа сервер рассылает событие `player_submitted`:
  ```json
  {
    "type": "player_submitted",
    "payload": {
      "player_id": "<uuid>"
    }
  }
  ```
  Текст ответа **ни при каких условиях** не передаётся по WebSocket до наступления фазы голосования!
- **Атомарный переход при 100% готовности:**
  - Количество сданных ответов отслеживается через атомарный инкремент в Redis: `INCR room:{code}:round:{round_id}:submitted`.
  - При достижении количества активных игроков фаза завершается досрочно ровно один раз (без race conditions от одновременных ответов).

---

## 2. Предлагаемые изменения по файлам

### Backend (`backend/`)
- `app/models/bluff.py`: SQLModel таблица `bluff_answers` (`id`, `round_id`, `player_id`, `answer_text`, `is_fallback`).
- `app/services/bluff_validator.py`: валидация текста с алгоритмом Fuzzy Matching (библиотека `rapidfuzz` или кастомное расстояние Левенштейна).
- Атомарная обработка WS-события `submit_bluff` с рассылкой `player_submitted`.

### Client (`client/`)
- `ui/screens/game/bluff_input_screen.dart`: поле ввода ответа (1–80 символов), кнопка «ОБМАНУТЬ ВСЕХ», вывод подсказок и ошибок валидации.
- `ui/screens/game/widgets/waiting_players_list.dart`: 8-bit список игроков комнаты с галочками готовности.

## 3. План верификации
- **Pytest:** юнит-тесты алгоритма Fuzzy Matching (детекция опечаток, артиклей, похожих слов), проверка атомарности досрочного перехода, проверка отсутствия текста ответов в WS payload.
- **Flutter test:** виджет-тест экрана ввода блефа и отображения статуса готовности.
