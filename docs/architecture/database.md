# Database Architecture — Quete

> [!NOTE]
> Схемы таблиц PostgreSQL, индексы, связи и политика миграций Alembic.
> Актуален на Спринт 1 (скелет). Обновляется по мере добавления фич.

## Схема базы данных

### Текущий статус
Спринт 1 завершён. Таблицы будут добавляться начиная со Спринта 2.

### Таблицы (планируются)

```text
players           — учётные записи гостевых игроков (JWT Guest Auth)
game_rooms        — лобби / игровые комнаты
game_sessions     — активные игровые сессии (State Machine)
rounds            — раунды внутри сессии
questions         — кэш сгенерированных ИИ вопросов
bluff_answers     — ответы-фейки от игроков и AI Auto-Fallback
votes             — голоса игроков в раунде
```

## Соглашения

- Все первичные ключи — UUID (генерация на стороне БД).
- Все таблицы имеют поля `created_at TIMESTAMPTZ` и `updated_at TIMESTAMPTZ`.
- Внешние ключи — с `ON DELETE CASCADE`, если дочерняя запись не имеет смысла без родителя.
- Индексы создаются явно в миграциях Alembic.

## Migrations Policy

- Каждая миграция — один атомарный изменяемый объект.
- Команда создания: `uv run alembic revision --autogenerate -m "описание изменения"`
- Применение миграций: `uv run alembic upgrade head`
- **ЗАПРЕЩЕНО** редактировать уже применённые миграции. Только новые ревизии.

## Redis (Сессии)

- `session:{player_id}` — онлайн-статус игрока. TTL: 30 сек (heartbeat).
- `room:{room_code}:players` — список игроков в лобби (Set).
- `question_cache:{topic}` — кэш вопросов от Gemini. TTL: 24 часа.
