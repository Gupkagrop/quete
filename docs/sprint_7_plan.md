# Спринт 7: Отказоустойчивость — «Auto-Fallback и Слияние ответов» (День 43–49)

## Goal Description
Цель седьмого спринта — обеспечить полную отказоустойчивость игрового процесса: автоматическую генерацию фейковых ответов (Auto-Fallback) при таймаутах или дисконнектах игроков с защитой от дублирования на уровне БД, алгоритм дедупликации/слияния одинаковых ответов от разных участников с записью в `rounds.voting_options` и честным делением очков, а также бесшовное восстановление состояния при реконнекте через `GET /rooms/{code}/state`.

---

## 1. Архитектурные решения

### 1.1 Механизм Auto-Fallback и защита от гонок (Race Condition)
- Если по истечении 45 секунд таймера игрок не отправил ответ или находится в оффлайне:
  - Сервер берёт один из неиспользованных вариантов `decoy_fallbacks` (из 7 доступных в вопросе) или локального пула.
  - Создаёт запись в `bluff_answers` с флагом `is_fallback = True`.
- **Защита от гонки «Таймаут против ответа в последнюю миллисекунду»:**
  - В таблице `bluff_answers` действует ограничение **`UNIQUE(round_id, player_id)`**.
  - Если ручной ответ игрока и задача таймаута сталкиваются одновременно, попытка второй вставки перехватывается как `IntegrityError` без дублирования ответов.

### 1.2 Алгоритм слияния одинаковых ответов (Deduplication & Merge)
- Если несколько игроков написали одинаковый (или нормализованно идентичный) ответ:
  - Варианты нормализуются (trim, lowercase, пунктуация).
  - В массив `rounds.voting_options` (JSONB) записывается **один** уникальный элемент с несколькими авторами:
    ```json
    {
      "id": "c1a2b3d4-...",
      "text": "Рим",
      "is_truth": false,
      "author_player_ids": ["player_a_uuid", "player_b_uuid"]
    }
    ```
  - **Честное деление очков:** при голосовании за этот `option_id` награда +500 делится поровну между всеми соавторами (`+500 / count`) и начисляется в `session_players.score`.

### 1.3 Синхронизация при реконнекте (State Recovery)
- При обрыве соединения клиент использует exponential backoff.
- После открытия WS-соединения клиент **выполняет REST-запрос `GET /rooms/{code}/state`**.
- Сервер возвращает актуальный снимок игры: активная фаза, таймер, список `voting_options` (с анонимизацией авторов) и статус сдачи ответа/голоса. Экран мгновенно восстанавливается без сброса игры.

## 2. Предлагаемые изменения по файлам

### Backend (`backend/`)
- Добавление `UNIQUE(round_id, player_id)` в миграцию таблицы `bluff_answers`.
- `app/services/fallback_service.py`: подстановка ИИ-фейков с идемпотентным перехватом конфликтов вставки.
- `app/services/answer_merger.py`: алгоритм нормализации, слияния дубликатов и записи в `rounds.voting_options`.
- REST эндпоинт `GET /rooms/{code}/state`: полная отдача стейта на базе сохранённых в БД данных.

### Client (`client/`)
- `ui/widgets/reconnect_banner.dart`: 8-bit баннер «Связь потеряна. Переподключение...».
- Интеграция автоматического вызова `GET /rooms/{code}/state` в `WebSocketService` и `GameProvider`.
