# Спринт 7: Краевые случаи — «Auto-Fallback и Слияние» (День 43–49)

## Goal Description
Цель седьмого спринта — обеспечить отказоустойчивость игрового процесса: автоматическая генерация фейковых ответов через ИИ (Auto-Fallback) при таймаутах или дисконнектах игроков, алгоритм дедупликации/слияния одинаковых ответов от разных участников и бесшовное восстановление состояния при реконнекте.

---

## 1. Архитектурные решения

### 1.1 Механизм Auto-Fallback (ИИ-страховка)
- Если по истечении 45 секунд таймера игрок не отправил ответ или находится оффлайн:
  - Сервер берёт один из неиспользованных `decoy_fallbacks` из сущности `Question`.
  - Создаёт запись в `bluff_answers` с флагом `is_fallback = True` от имени неактивного игрока.
  - Игра **никогда не зависает** в ожидании людей.

### 1.2 Алгоритм слияния одинаковых ответов (Deduplication & Merge)
- Если Игрок А написал «Рим» и Игрок Б написал «рим»:
  - Варианты нормализуются (trim + lower).
  - В пул голосования отдаётся **один** уникальный вариант.
  - В памяти сервера сохраняются оба автора: `authors: [player_a_id, player_b_id]`.
  - При голосовании за этот вариант оба автора получат положенные очки!

### 1.3 Синхронизация при реконнекте (State Recovery)
- При разрыве соединения и повторном подключении игрока сервер отправляет событие `sync_game_state` с текущей активной фазой, оставшимся временем и статусом ответа игрока.

## 2. Предлагаемые изменения по файлам

### Backend (`backend/`)
- `app/services/fallback_service.py`: логика подстановки ИИ-фейков за неактивных игроков.
- `app/services/answer_merger.py`: алгоритм нормализации и слияния дублирующихся ответов.
- WebSocket обработка повторного подключения с отправкой полного снимка состояния комнаты.

### Client (`client/`)
- `ui/widgets/reconnect_banner.dart`: 8-bit баннер «Связь потеряна. Переподключение...».
- Обработка `sync_game_state` в `GameProvider` с автоматическим роутингом на экран текущей фазы матча.
