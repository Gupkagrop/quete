# 🗺️ План реализации (Roadmap) проекта «Quete» на 70 дней

## Описание цели
Создание Production-Ready мультиплеерной квиз-игры с механикой блефа («Quete») за 70 дней (10 спринтов по 7 дней). 
Игра разрабатывается для Web, Android, iOS и Windows (с фокусом на Mobile-First и вертикальную ориентацию).
Главная геймплейная особенность — интеграция с Google Gemini 1.5 Flash (генерация вопросов через Structured Outputs и динамический Auto-Fallback за отключившихся игроков).

## 🏗️ Архитектурные решения
- **Подход к разработке:** Вертикальная нарезка (Feature-by-Feature). Бэкенд и UI каждой фичи разрабатываются параллельно в рамках одного спринта.
- **Инфраструктура и деплой:** Docker Compose (PostgreSQL 16, Redis 7). Автоматический CI/CD через GitHub Actions для ветки `dev`.
- **Backend:** Python 3.12+, FastAPI (асинхронный), SQLModel + Alembic, Redis (сессии и онлайн). Пакетный менеджер: строго `uv`.
- **Client (Flutter):** Стейт-менеджмент через **Riverpod** (`AsyncNotifier`), декларативная маршрутизация через **`go_router`**.
- **Дизайн-система:** Процедурный 8-bit ретро-стиль (неоновая палитра `#0D0D0D`, `#00FF41`, `#FF00FF`, пиксельные шрифты, CustomPainter CRT-сканлайны).
- **Связь в реальном времени:** WebSockets со строгим envelope-форматом `{"type": str, "payload": dict}`.

## 📅 Детальный план по спринтам (10 недель)

### Спринт 1: Инфраструктура, Монорепозиторий и БД (День 1–7) ✅ [ЗАВЕРШЁН]
- Инициализация монорепозитория (`backend/`, `client/`).
- Настройка `docker-compose.yml` (PostgreSQL 16, Redis 7).
- Инициализация бэкенда: `uv`, FastAPI, SQLModel, настройка миграций Alembic.
- Создание базового скелета Flutter-приложения с Riverpod и `go_router`.
- Настройка CI/CD пайплайна (GitHub Actions) для автотестов.

### Спринт 2: Фича «Авторизация и Сессии» (День 8–14) 🔄 [ТЕКУЩИЙ]
- **Backend:** JWT Guest Auth (генерация 6-значного PIN-кода для восстановления). Redis-сессии для отслеживания онлайна. Модель `Player` и миграция Alembic.
- **Client:** Базовая 8-bit дизайн-система (тема, кнопки). Экран входа (`AuthScreen`). Riverpod `AuthProvider`. Редирект-гард в `go_router`.

### Спринт 3: Фича «Лобби и WebSockets» (День 15–21)
- **Backend:** WebSocket `ConnectionManager`. Управление комнатами: создание (`POST /rooms`), подключение (`POST /rooms/{code}/join`), передача хоста при дисконнекте.
- **Client:** WebSocket клиент с авто-реконнектом (exponential backoff). Экран лобби (`LobbyScreen`), список игроков, бейдж хоста, кнопка старта.

### Спринт 4: Фича «Генерация вопросов ИИ» (День 22–28)
- **Backend:** Интеграция Gemini 1.5 Flash через Structured Outputs (Pydantic). Таблица `questions` и кэширование в PostgreSQL/Redis. Выбор темы (3 случайные + своя тема).
- **Client:** Экран/диалог выбора темы (`TopicSelectionScreen`). Ретро-состояние ожидания генерации с пиксельной анимацией.

### Спринт 5: Игровой цикл — «Вопрос и Таймеры» (День 29–35)
- **Backend:** State Machine игры: переход комнаты в фазу вопроса. Широковещательная рассылка вопроса и запуск серверного таймера. Таблицы `game_sessions` и `rounds`.
- **Client:** Экран чтения вопроса (`GameQuestionScreen`). Виджет синхронизированного 8-bit таймера (`PixelTimer`) с цветовой индикацией.

### Спринт 6: Игровой цикл — «Блеф» (День 36–42)
- **Backend:** Фаза ввода ложных ответов (`submit_bluff`). Валидация на несовпадение с правдой. Таблица `bluff_answers`. Оповещение комнаты о готовности игроков.
- **Client:** UI ввода фейкового ответа. Экран ожидания остальных игроков с индикаторами готовности.

### Спринт 7: Краевые случаи — «Auto-Fallback и Слияние» (День 43–49)
- **Backend:** Автоматическая генерация фейков через Gemini при таймауте или дисконнекте игрока. Алгоритм слияния одинаковых ответов от разных игроков. Синхронизация состояния при реконнекте.
- **Client:** Плавная обработка дисконнектов/реконнектов, автоматическое восстановление состояния экрана по WS без сброса игры.

### Спринт 8: Игровой цикл — «Голосование и Подсчёт очков» (День 50–56)
- **Backend:** Рассылка перемешанных вариантов (правда + фейки). Сбор голосов. Начисление очков (+1000 за правду, +500 за обман соперника). Таблица `votes` и лидерборд.
- **Client:** Экран голосования (`VotingScreen`). Экран результатов раунда (`RoundResultScreen`) с анимацией раскрытия обмана и таблицей лидеров.

### Спринт 9: Полировка и 8-bit дизайн (День 57–63)
- **Client:** Процедурный CRT-эффект (CustomPainter сканлайнов, легкое мерцание, виньетка). 8-bit звуковые эффекты. Адаптивность (Mobile, Tablet, Desktop, Web). Локализация i18n (RU/EN).
- **Backend:** Профилирование WebSocket соединений, нагрузочное тестирование комнат, оптимизация индексов БД.

### Спринт 10: Финальный QA и Релиз (День 64–70)
- End-to-End тестирование полного матча (4 клиента).
- Контейнеризация бэкенда (`Dockerfile` с `uv`, `docker-compose.prod.yml`).
- Деплой бэкенда на production VPS и хостинг Flutter Web-версии.
- Финальная документация проекта и сдача.

## 🛡️ Правила разработки и верификации
1. **Тесты:** Никаких пушей фичей без написанных автотестов (`pytest` / `flutter test`).
2. **CI/CD Pipeline:** Автоматический запуск тестов при каждом push в ветку `dev`.
3. **E2E ручное тестирование:** Перед мерджем фичей с WS создается локальная сессия с 3–4 клиентами.
