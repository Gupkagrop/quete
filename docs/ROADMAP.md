# 🗺️ План реализации (Roadmap) проекта «Quete» на 70 дней

## Описание цели
Создание Production-Ready мультиплеерной квиз-игры с механикой блефа («Quete») за 70 дней (10 спринтов по 7 дней). 
Игра разрабатывается для Web, Android, iOS и Windows (с фокусом на Mobile-First и вертикальную ориентацию).
Главная геймплейная особенность — интеграция с Google Gemini 1.5 Flash (генерация вопросов через Structured Outputs и динамический Auto-Fallback за отключившихся игроков).

---

## 🏗️ Архитектурные решения
- **Подход к разработке:** Вертикальная нарезка (Feature-by-Feature / MVP-First). Бэкенд и UI каждой фичи разрабатываются параллельно в рамках одного спринта с обеспечением играбельного состояния ядра уже к середине проекта.
- **Инфраструктура и деплой:** Docker Compose (PostgreSQL 16, Redis 7). Автоматический CI/CD через GitHub Actions для ветки `dev`.
- **Backend:** Python 3.12+, FastAPI (асинхронный), SQLModel + Alembic, Redis (сессии, Distributed Locks, Rate Limiting, Pub/Sub). Пакетный менеджер: строго `uv`.
- **Real-time шина (WebSockets):** Рассылка сообщений через **Redis Pub/Sub** для поддержки распределенной работы нескольких воркеров Uvicorn. Безопасная аутентификация через первое сервисное сообщение `auth` (токены не передаются в URL).
- **Синхронизация состояния (State Recovery):** При любом реконнекте клиент восстанавливает состояние через `GET /rooms/{code}/state`, что исключает рассинхронизацию при потере сетевых пакетов.
- **Client (Flutter):** Стейт-менеджмент через **Riverpod** (`AsyncNotifier`), декларативная маршрутизация через **`go_router`**.
- **Дизайн-система:** Процедурный 8-bit ретро-стиль (неоновая палитра `#0D0D0D`, `#00FF41`, `#FF00FF`, пиксельные шрифты, резкие границы, CRT-сканлайны).

## 📅 Детальный план по спринтам (10 недель)

### Спринт 1: Инфраструктура, Монорепозиторий и БД (День 1–7) ✅ [ЗАВЕРШЁН]
- Инициализация монорепозитория (`backend/`, `client/`).
- Настройка `docker-compose.yml` (PostgreSQL 16, Redis 7).
- Инициализация бэкенда: `uv`, FastAPI, SQLModel, настройка миграций Alembic.
- Создание базового скелета Flutter-приложения с Riverpod и `go_router`.
- Настройка CI/CD пайплайна (GitHub Actions) для автотестов.

### Спринт 2: Фича «Авторизация и Сессии» (День 8–14) ✅ [ЗАВЕРШЁН]
- **Backend:** JWT Guest Auth с генерацией 6-значного PIN-кода для восстановления.
  - Хэширование PIN-кода через `bcrypt`.
  - Rate Limiting на базе Redis (максимум 5 попыток ввода PIN в минуту, защита от brute-force).
  - Валидация никнейма по строгому regex `^[a-zA-Z0-9_-]{2,20}$`.
  - Разделение ключей Redis: `session:{player_id}` (авторизация, TTL 30 дней) и `online:{player_id}` (heartbeat, TTL 30 сек).
  - Grace Period (30–60 сек) для ротации refresh-токенов в мобильных сетях.
- **Client:** Базовая 8-bit дизайн-система (тема, кнопки). Экран входа (`AuthScreen`). Riverpod `AuthProvider`. Редирект-гард в `go_router`.

### Спринт 3: Фича «Лобби и WebSockets» (День 15–21) 🔄 [СЛЕДУЮЩИЙ]
- **Backend:** WebSocket `ConnectionManager` на базе **Redis Pub/Sub** (поддержка мульти-воркерной среды). Аутентификация сокета через handshake-сообщение (без токена в URL). Фоновая сборка мусора (Garbage Collection) для заброшенных комнат (Zombie Rooms).
- **Client:** WebSocket клиент с авто-реконнектом (exponential backoff). REST эндпоинт `GET /rooms/{code}/state` для мгновенной синхронизации при переподключении. Экран лобби (`LobbyScreen`), список игроков, бейдж хоста, кнопка старта.

### Спринт 4: Фича «Генерация вопросов ИИ» (День 22–28)
- **Backend:** Интеграция Gemini 1.5 Flash через Structured Outputs (Pydantic). 
  - Схема с 7 ложными вариантами `decoy_fallbacks` (для комнат до 8 человек).
  - Защита от Prompt Injection в пользовательских темах квиза.
  - Redis Distributed Lock на уровне комнаты `room:{code}:lock` для предотвращения одновременных запросов генерации.
  - Двухуровневый кэш (Redis/БД) и резервный пул вопросов в PostgreSQL на случай сбоев Google API.
- **Client:** Экран/диалог выбора темы (`TopicSelectionScreen`). Ретро-состояние ожидания генерации с пиксельной анимацией.

### Спринт 5: Игровой цикл — «Core Game Loop MVP» (День 29–35) 🎮
- **Backend:** Полноценный играбельный цикл одного раунда: State Machine (`QUESTION_READING` $\rightarrow$ `BLUFF_SUBMISSION` $\rightarrow$ `VOTING` $\rightarrow$ `ROUND_RESULTS`). Таймеры по меткам `phase_ends_at` в Redis. Базовая валидация блефа и подсчёт очков (+1000 за истину, +500 за блеф). Рассылка через Redis Pub/Sub.
- **Client:** Полный флоу экранов одного раунда: Чтение вопроса (`GameQuestionScreen`) $\rightarrow$ Ввод лжи (`BluffInputScreen`) $\rightarrow$ Голосование (`VotingScreen`) $\rightarrow$ Результаты раунда (`RoundResultScreen`). Синхронизированный таймер `PixelTimer`.
- **Результат:** 100% играбельный матч от старта до показа очков на тестовом пуле вопросов!

### Спринт 6: Интеллектуальный геймплей — «ИИ-вопросы и Нечеткая валидация» (День 36–42)
- **Backend:** Подключение генератора вопросов Gemini (Спринт 4) к игровым сессиям. Интеллектуальная валидация блефа через **Fuzzy Matching** (`rapidfuzz`, порог схожести >80% против случайного раскрытия истины). Атомарный счетчик готовности игроков в Redis с защитой от гонок при досрочном переходе. Сокрытие текста ответов в событии `player_submitted`.
- **Client:** Подключение живых тем и вопросов ИИ в интерфейс игры, визуальная обратная связь при срабатывании Fuzzy Matching (`BLUFF_MATCHES_TRUTH`), ретро-список ожидания игроков с галочками готовности.

### Спринт 7: Отказоустойчивость — «Auto-Fallback и Слияние ответов» (День 43–49)
- **Backend:** Автоматическая генерация фейков (Auto-Fallback) из 7 `decoy_fallbacks` при таймауте/дисконнекте. Ограничение `UNIQUE(round_id, player_id)` в `bluff_answers` для исключения гонки между таймаутом и ручным ответом. Алгоритм слияния одинаковых ответов (Deduplication & Merge) со справедливым делением очков (`+500 / N`) между соавторами.
- **Client:** Плавная обработка дисконнектов/реконнектов, автоматический вызов `GET /rooms/{code}/state` без сброса игры, баннер `ReconnectBanner`.

### Спринт 8: Турнирный финал — «Матч и Таблица лидеров» (День 50–56)
- **Backend:** Управление полным матчем из 5 раундов, переход в финальный статус `GAME_FINISHED`. Ограничение `UNIQUE(round_id, voter_id)` против множественного голосования. Сохранение итогов матча в БД, расчет финальной турнирной таблицы.
- **Client:** Экран финальных результатов матча (`LeaderboardScreen`), 8-bit пьедестал почета для топ-3 игроков с кубком, кнопка возврата в лобби/рестарта.

### Спринт 9: Полировка и 8-bit дизайн (День 57–63)
- **Client:** Процедурный CRT-эффект (CustomPainter сканлайнов, легкое мерцание, виньетка). 8-bit звуковые эффекты. Адаптивность (Mobile, Tablet, Desktop, Web) с аркадным корпусом `ArcadeCabinetFrame`. Локализация i18n (RU/EN).
- **Backend:** Профилирование WebSocket соединений под нагрузкой, аудит Redis Pub/Sub каналов, фоновая очистка (Pruning) неактивных гостевых аккаунтов.

### Спринт 10: Финальный QA и Релиз (День 64–70)
- End-to-End тестирование полного матча (4 клиента через вебсокеты).
- Контейнеризация бэкенда (`Dockerfile` с `uv`, запуск с несколькими воркерами Uvicorn, `docker-compose.prod.yml`, Nginx с WS upgrade).
- Деплой бэкенда на production VPS и хостинг Flutter Web-версии.
- Финальная документация проекта и сдача.

## 🛡️ Правила разработки и верификации
1. **Тесты:** Никаких пушей фичей без написанных автотестов (`pytest` / `flutter test`).
2. **CI/CD Pipeline:** Автоматический запуск тестов при каждом push в ветку `dev`.
3. **E2E ручное тестирование:** Перед мерджем фичей с WS создается локальная сессия с 3–4 клиентами.
