## 📁 2. Где что лежит на сервере (Важные пути)

*   **`/var/www/quete/`** — Основная папка сайта со всеми PHP, JS и CSS файлами.
*   **`/var/www/quete/.env`** — Файл конфигурации окружения (настройки подключения к БД, ключи Groq API и настройки сокета).
    *   *Как отредактировать:* `nano /var/www/quete/.env` (для сохранения изменений нажми `Ctrl + O`, затем Enter; для выхода `Ctrl + X`).
*   **`/etc/nginx/sites-available/quete`** — Конфигурация веб-сервера Nginx (правила маршрутизации и проксирования сокетов).
*   **`/etc/systemd/system/quete-websocket.service`** — Конфигурация службы автозапуска WebSocket-сервера.

## ⚡ 3. Основные команды управления сервером

Все эти команды нужно выполнять в консоли сервера после подключения через SSH.

### 🔌 WebSocket-сервер (Игровая логика в реальном времени)
Игра использует фоновый сервер Ratchet на PHP. Он работает как системная служба `quete-websocket`.

*   **Проверить, работает ли WebSocket:**
    ```bash
    systemctl status quete-websocket
    ```
    *(Если всё хорошо, ты увидишь зеленую надпись `active (running)`).*
*   **Перезапустить WebSocket (например, после обновления кода):**
    ```bash
    systemctl restart quete-websocket
    ```
*   **Остановить WebSocket-сервер:**
    ```bash
    systemctl stop quete-websocket
    ```
*   **Запустить WebSocket-сервер:**
    ```bash
    systemctl start quete-websocket
    ```

### 🌐 Nginx (Веб-сервер, раздающий сайт и SSL)
Nginx отвечает за работу ссылок `https://quete.ru` и проксирование запросов к WebSocket.

*   **Проверить статус Nginx:**
    ```bash
    systemctl status nginx
    ```
*   **Перезапустить Nginx (сбросить кэш и применить настройки):**
    ```bash
    systemctl restart nginx
    ```
*   **Проверить конфигурацию Nginx на ошибки:**
    ```bash
    nginx -t
    ```

## 📝 4. Просмотр логов (Где искать ошибки)

Если в игре что-то идет не так, игроки не могут подключиться или ИИ зависает, лог-файлы помогут понять причину.

*   **Посмотреть последние 50 строк логов WebSocket (в реальном времени):**
    ```bash
    journalctl -u quete-websocket -n 50 -f
    ```
    *(Нажми `Ctrl + C` для выхода из режима просмотра).*
*   **Посмотреть ошибки веб-сервера Nginx:**
    ```bash
    tail -n 50 /var/log/nginx/error.log
    ```

## 💾 5. Работа с Базой Данных (Резервные копии SQL)

На сервере установлена СУБД MySQL. Имя базы данных — `quete_db`.

*   **Создать резервную копию (бэкап) базы данных:**
    ```bash
    mysqldump -u root -p quete_db > /var/www/quete/database_backup.sql
    ```
    *(После нажатия Enter скрипт попросит ввести пароль от MySQL — введи пароль от базы данных из `.env` файла).*
*   **Восстановить базу данных из резервной копии:**
    ```bash
    mysql -u root -p quete_db < /var/www/quete/database_backup.sql
    ```

## 🛠️ 6. Решение частых проблем (Troubleshooting)

### 🚨 Проблема: Игроки видят ошибку *"WebSocket сервер не обнаружен"*
**Что делать:**
1. Подключись к серверу по SSH.
2. Перезапусти службу WebSocket:
   ```bash
   systemctl restart quete-websocket
   ```
3. Проверь статус службы:
   ```bash
   systemctl status quete-websocket
   ```
4. Если служба показывает ошибку, посмотри логи ошибок:
   ```bash
   journalctl -u quete-websocket -n 20 --no-pager
   ```

### 🚨 Проблема: Игра работает локально, но на сервере изменения не появились
**Что делать:**
1. Возможно, твой браузер кэшировал старые скрипты или стили CSS. Нажми **`Ctrl + F5`** (или `Cmd + Shift + R` на Mac) на странице игры для принудительного обновления кэша.
2. Если не помогло, убедись, что новые файлы были действительно отправлены на сервер (для этого запусти скрипт `python scratch/compare_files.py` в локальной папке проекта).
