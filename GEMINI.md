## 🔒 1. Критические ограничения (Не нарушать ни при каких обстоятельствах)
*   **Подтверждение прочтения:** В самом первом ответе каждого диалога обязательно напиши в чат фразу: `Контекст учтён!!!`.
*   **Обязательное чтение руководства по деплою:** Если задача или запрос пользователя требует взаимодействия с сервером VPS (выполнение команд, деплой файлов, перезапуск служб, проверка логов, настройка UFW и т.д.), ИИ-ассистент **обязан первым делом** полностью прочитать файл [DEPLOYMENT_GUIDE_AGENT.md]. Только после этого разрешается выполнять команды и операции на сервере.
*   **Запрет на редактирование ядерных файлов:** Категорически запрещено изменять любые `.sql` файлы и файл ядра `core/ai_handler.php` без явного разрешения и предварительного одобрения пользователя.
*   **Сохранение стиля CSS:** Запрещено полностью перезаписывать или заменять `.css` файлы. Разрешено только точечно корректировать и исправлять отображение элементов. Внешний вид сайта должен строго сохранять свой ретро-дизайн.
*   **Адаптивность:** При любых корректировках CSS обязательно проверяй корректность отображения на мобильных устройствах (смартфонах и планшетах).

## 📖 2. Понимание архитектуры и процессов
*   **Глубокий технический анализ:** ИИ-ассистент **обязан** детально изучить файл [deepAnalysis.md] для полного понимания сетевой архитектуры, билетной WebSocket-авторизации, leetspeak-устойчивой цензуры, работы СУБД и стандартов мобильной адаптивности CSS.
*   **Структура БД:** Изучи структуру базы данных по дампу `database.sql` и по техническому манифесту `GENERAL.md`.
*   **Игровая логика и WebSocket:** Динамическое обновление сайта и передача игровых событий осуществляются в реальном времени через технологию WebSocket (Ratchet).
*   **Техническое руководство:** Вся актуальная информация о структуре, функциях, методах и архитектуре игры объединена в мастер-файле `GENERAL.md`. Обращайся к нему перед написанием любого кода.
*   **Изучение документации:** Перед началом крупных доработок изучи все `.md` файлы в проекте, чтобы до конца понять принципы функционирования сайта.

## ✍️ 3. Требования к качеству кода и коммуникации
*   **Безопасность и чистота:** Пиши безопасный, понятный и лаконичный код. Обязательно снабжай новые блоки подробными комментариями на русском языке.
*   **Никакой самодеятельности:** Если в игровой логике или требованиях есть неточности, двусмысленности или вопросы — обязательно задавай их пользователю в чате. Не додумывай логику самостоятельно!
*   **Ведение журнала работ:** Подробно записывай все выполненные изменения, исправления багов и улучшения в файл `COMPLETED_WORK.md` в корне проекта.

## ⚡ 4. Оптимизация ресурсов и квот (Экономный режим)
*   **Эффективные итерации:** Старайся решать задачи за минимальное число шагов. Объединяй точечные правки в один вызов инструмента редактирования вместо совершения нескольких последовательных мелких запросов к API.
*   **Бережный расход токенов:** Избегай повторного чтения больших файлов, если они не менялись с момента последнего просмотра. Не сканируй тяжелые системные директории (например, `/vendor`), если в этом нет крайней технической необходимости.
*   **Лаконичность без потери качества:** Излагай мысли емко, избегая избыточных приветствий и дублирования текста. При этом качество кода, подробность комментариев на русском языке и ведение журнала `COMPLETED_WORK.md` должны оставаться на высшем уровне.

## 🛠️ 5. Использование MCP-серверов (Инструкции для ИИ)
В среде разработки проекта Quete настроены 6 MCP-серверов. ИИ-ассистент обязан использовать их возможности для оптимизации работы и строгого следования правилам безопасности:

1. **MySQL MCP Server** (`mysql`):
   * **Когда использовать**: При получении любых задач, связанных со структурой БД, написанием SQL-запросов, проверкой DDL/DML, отладкой лобби или пользователей.
   * **Действие**: Перед модификацией кода проверьте схему таблицы через MCP-инструменты базы данных.

2. **Git MCP Server** (`git`):
   * **Когда использовать**: Для поиска авторов изменений, анализа истории разработки, формирования списков изменений перед их документированием в `COMPLETED_WORK.md`.
   * **Действие**: Анализируйте коммиты с помощью MCP-инструментов Git.

3. **Playwright MCP Server** (`playwright`):
   * **Когда использовать**: При любых изменениях CSS/HTML фронтенда и логики WebSockets в `game.php` или `solo.php`.
   * **Действие**: Запускайте автоматический браузер для визуального контроля, делайте скриншоты и тестируйте WebSocket-подключение в реальном времени.

4. **SSH / Bash MCP Server** (`ssh-mcp`):
   * **Когда использовать**: При деплое, администрировании VPS или проверке логов службы Ratchet.
   * **Действие**: Выполняйте удаленные команды через SSH MCP-инструменты согласно правилам `DEPLOYMENT_GUIDE_AGENT.md`.

5. **Memory MCP Server** (`memory`):
   * **Когда использовать**: Для фиксации важных архитектурных связей и выработанных решений в Графе Знаний.

6. **Lighthouse MCP Server** (`lighthouse`):
   * **Когда использовать**: При изменении дизайна, стилей CSS, медиа-ресурсов, верстки или внедрении новых скриптов для оценки влияния изменений на производительность и SEO.
   * **Действие**: Запускайте аудит веб-страниц (Core Web Vitals, доступность, SEO, безопасность) для своевременного обнаружения просадок скорости загрузки и соответствия стандартам.
